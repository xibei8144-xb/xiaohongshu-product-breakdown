# 视觉与出图说明

## 1、视觉基线

原生竖版 1080×1440，通常左右安全边距 72 px；正文约 27–32 px，主要标题约 55–61 px。这些是起点，需在手机缩略尺寸检查。减少重复文字、调整结构，不用巨型标题撑版，也不靠缩小正文塞内容。保留亮白底、深色正文；产品色主要用于局部浅色块、编号和重点。

每页建立“问题标题 → 信息分块 → 必要图注”的层级。卡片通过位置、间距和适量色块清楚分组，不把所有内容切成同样大小的框。文字与截图共同解释一个问题，不堆无关装饰。

封面沿用账号已确认的结构和字体，间距与字号可微调。头像按原图等比裁切；测量实际字形宽度，把头像、间距、名字作为整体居中。圆角容器简洁，留足内边距。末页的点赞／收藏／关注是主要信息，文字可从 44–50 px 起试排，不缩成页脚小字。

Logo 保留原色与比例，投影清楚但边缘柔和。官方 SVG 转换后核对轮廓、细节和颜色；若渲染器未解析样式，修复样式解析，不凭印象重画标识。

截图先看原图，再裁相关区域。区分整页坐标和视口坐标，核对实际裁出的是目标界面；宽大工作区可选关键局部，保留理解所需上下文。手机尺寸下看不清的整屏截图应改为局部图，并用短图注说明素材性质。

## 2、原生 Canvas 脚本

`render.cjs` 是历史七页实现，固定页数和数组长度不能直接适配任意内容。按新稿修改布局后再使用，或另写原生图片排版脚本；不为了兼容脚本凑页、凑卡片。没有明确要求时延续已确认的风格。

依赖 Node.js 和 `@napi-rs/canvas`。脚本优先加载普通 Node 模块，也兼容本机 Codex 缓存运行时；可通过 `XHS_CANVAS_MODULE` 指向模块，`XHS_FONT_PATH` 指定中文字体。依赖缺失时先查询本地运行时路径，不盲目安装包。

```sh
node <skill-dir>/scripts/render.cjs \
  --content <work-dir>/content.json \
  --assets <work-dir>/assets \
  --out <work-dir>/output
python3 <skill-dir>/scripts/package.py \
  --content <work-dir>/content.json \
  --out <work-dir>/output
```

头像通过 `--brand` 中的 avatar 或 `--avatar` 提供；未提供时省略头像。账号名、栏目和标语的配置见 [安装与账号配置](setup.md)。不覆盖已有成稿，调整版本时使用新的输出目录。脚本不联网、不发起任务，也不发布内容。

可使用 `assets/example-content.json` 测试渲染；先运行 `python3 scripts/fetch_example_assets.py` 下载对应官方素材。该脚本的第三方输入素材不随仓库分发；另有[扣子成品示例](../examples/coze/README.md)供观察完整输出，成图内含已注明来源的产品素材。示例事实是历史资料，正式制作其他产品必须重新研究，不把示例文案复制成新产品内容。

历史脚本输出每款 `images/01.png...07.png`、布局报告、总览、发布文案和来源文件。打包器按 `pageCount`（缺省为 7）读取编号图片和布局报告，生成纯图片 ZIP、文案合集及 `delivery-manifest.json`。改变页数后同步设置该字段与实际输出，不能只修改文案。

## 3、内容 JSON 字段

顶层为产品数组。所有长文先编写、精简，再交给渲染器。下面数组数量仅适用于当前七页版式；要变更内容数量须同时修改版式。

| 字段 | 格式与用途 |
| --- | --- |
| `id, name, sub` | 安全目录名、产品名、封面一句话定位 |
| `color, pale` | 产品强调色、轻底色；均为颜色值 |
| `logo, shot, shot2` | 相对 `--assets` 的真实文件；流程图模式可省略 shot2 |
| `intro, desc` | 概述标题两行数组；正文字符串，支持换行 |
| `cards` | 当前版四个 `[标题, 两行说明]` |
| `note` | 概述页一句观察 |
| `feature, fd, shotlabel, rows` | 核心页 `[眉题, 标题上行, 标题下行]`、说明、素材性质、三组 `[标签, 说明]` |
| `flowtitle, flowdesc, flow, point` | 两行标题、说明、三组步骤、收束观察 |
| `feature2, fd2, shotlabel2, take` | 第二能力页标题、说明、图注、观察 |
| `detailRows` | 可选，两组短对照，使用较小图片＋对照布局 |
| `diagram` | 可选，三组 `[标题, 说明]`，代替第二能力页的图片；标清编辑示意 |
| `who, prompt, limits` | 三组人群任务、三行示例、三条相关边界 |
| `end` | 结束页两句短文，避免空泛夸赞 |
| `title, caption, tags, sources` | 发布标题、正文、Tag 字符串、官方 URL 数组 |
| `pageCount` | 打包器使用的实际页数，缺省 7；不会自动改变渲染器的固定布局 |
| `robot` | 可选布尔，任务页采用机器人用语 |
| `researchNote` | 可选；按真实情况描述研究／实测性质，默认官方资料整理、未独立实测 |
| `coverLogoBackground` | 可选，Logo 承托块颜色 |
| `crop` | 可选 Logo 裁切 `[sx, sy, sw, sh]`，仅裁无关留白，不改变原标识 |

图片内容按等比 contain 放入页面；裁切行为需保留产品上下文。当前 `cropShot` 为历史细长局部截图版式，非通用裁切开关，通常不用。

## 4、验证与交付

渲染器输出文本边界检查，但不能自动发现全部重叠或判断审美。打包脚本验证的是可观察结构：PNG 尺寸、连续页序、布局报告、每包实际文件清单、哈希。

每款查看缩略总览，再放大封面、图片页和文字密集页。检查文本重叠、裁字、字号断层、图文比例、署名位置与素材细节。修复后重渲染受影响页，同步总览、文案和 ZIP；确认下载包中的图片就是最终版本。

图片 ZIP 只放编号 PNG；文案和来源另外提供。最终对话展示预览与两个主要入口（全量图片、文案），需要时再列单款链接，避免同时展示几十张大图拖慢阅读。
